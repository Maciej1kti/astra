# Goals — 2026-10-10

The owner asked for a round of changes to the web interface only; the iOS and
Mac apps follow later. Projects are called **Cele** (goals), a goal opens in a
dialog built like a card's, shows dates taken from its cards, and has its own
sub-view on Calendar and Timeline. The direction is in
[scope](SCOPE.md#goals--owner-direction-2026-10-10) and the decisions in
[ADR-079](../docs/ADR-079-GOAL-COMMENTS-AND-SPAN.md).

## What changed

- **Name.** Every Polish text in the browser says cel/cele where it said
  projekt/projekty: navigation, the header list, dialogs, menus, messages and
  Settings. Only the `.project` folder name stays. Identifiers, routes, the
  CLI, file formats and English documentation still say project.
- **Goal dialog.** The project editor uses the card's layout and components: an
  editable name, a status menu, the read-only range of the cards' dates, then
  description, comments and folder. No counters, dates of its own or
  checklists.
- **Dates from cards.** A project summary carries a derived `span`: the
  earliest start and latest end over its non-archived cards' plans and timed
  events. It is computed on each read, never stored and never accepted by a
  write. The **Cele** board shows it on each goal with the number of comments,
  and a card's date change reaches an open board without replaying its
  entrance.
- **Comments.** `project.json` gains an optional `comments` history appended
  through a third `ProjectPatch` variant, with the card rules: observed
  version, request identity, limits and no undo. `projectctl project comment`
  is the CLI counterpart.
- **Calendar and Timeline.** Both toolbars gained a **Karty | Cele** switch,
  kept in the address as `scope=goals`. The goal scope lays out every goal the
  workspace already holds over its range, reads nothing else and writes
  nothing: a bar cannot be moved or stretched and opens the goal. Timeline
  lists goals whose cards have no dates above the axis.

## Checks

macOS 27.0.1, Node 24.11, Chromium through Playwright, daemon from
`target/release` rebuilt with the new frontend.

- Rust: `fmt --check`, `clippy --workspace --all-targets -D warnings` and
  `test --workspace --locked` pass, 496 tests. New regressions cover the span
  (schedules, events across midnight, archived cards, milestones, both
  `archived` lists, search, a stale cursor after a date edit), project comment
  append, conflict, replay, limits, undo refusal, the context budget and the
  CLI command.
- Web: `npm run check` (contracts and `svelte-check`) 0 errors, `npm run lint`,
  `npm run format:check`, `scripts/check-boundaries.mjs` and
  `scripts/check_package.py` pass; the comment request examples are now
  validated against `CardPatch` and `ProjectPatch`. `npm run test:unit`: 582
  pass. `npm run check:bundle`: 81,823 of 81,920 bytes.
- Browser: `ASTRA_TEST_PROFILE=release npm run test:browser`. The CLI tag
  workflow, the smoke test and the planning script pass. Of the 45 regression
  suites 42 passed in that run. Two failed on expectations this change
  replaces and pass after their update: `autosave` AS09 required the project
  dialog to keep a margin on a 390 px phone, where it now fills the width as a
  card does, and `timeline` listed the toolbar's segments without **Karty** and
  **Cele**. The third, `projects`, timed out once waiting for the page's reads
  to finish after the lost-response retry. It then passed 19 times in a row on
  the same build and the cause is not established; the step now names the
  unfinished request when it fails. The full run was not repeated after these
  three suite edits, as no application file changed.
- The new `goals` suite drives the real daemon: dates on the board, a live
  range change after a CLI card patch, the card-shaped dialog, a human and a
  bot comment with inert markup, a status change that keeps comments, both goal
  scopes by pointer and keyboard, the address across back and forward, no write
  to a goal from either view, a 390 px phone, and another character, palette
  and spacing. Its pictures are under ignored
  `test-results/browser/regressions/goals/`.

## Rollout

The manual instance was restarted on the rebuilt release daemon with its
existing data, settings and certificate. At
`https://maciejs-mac-mini.tail69df8f.ts.net:47832`, `/healthz` answers 200 and
`/api/v1/bootstrap` 401, all 82 served files equal `apps/web/dist`, the users
are unchanged, and the agent and GitHub publication are still on. None of the
15 goals there has a range yet: the only dated card in that data is archived.

## Limits

- One unexplained failure of the `projects` suite in 20 runs, described above.
- Chromium only for the new suite's pictures; nothing was run on a physical
  phone, and the look awaits the owner's judgement.
- `apps/ios` was not touched. Its interface tests and the Mac app's look for
  the label **Projekty** and will fail against this build until they are
  updated with the apps.
- A daemon built before this change reports a `project.json` that already
  holds comments as invalid.
- On a phone the month list repeats a goal under every day it covers, as it
  does a card with a plan of several days.
